# Keeping Attribution Visible Under Apache 2.0

The Apache License 2.0 is intentionally permissive — it allows anyone to use, modify, and redistribute this project's code, including commercially, without needing to open-source their own derivative work. It does **not**, by itself, require downstream users to publicly credit the original author in a UI or marketing sense; it only requires that copyright, license, and NOTICE text be **retained in the Source form** (Section 4 of the license).

Because of this, professional, deliberate attribution practices are used throughout this project to keep authorship visible and credible **without changing the license terms or restricting reuse**. This is standard practice among well-known open-source projects and is fully compatible with maximising community adoption.

---

## 1. Legally Required (Apache 2.0 Section 4)

These are baked into the repository and **must be preserved** by anyone redistributing the code:

- The [`LICENSE`](../LICENSE) file, unmodified, in any redistribution.
- The [`NOTICE`](../NOTICE) file's attribution content, in any Derivative Work that is distributed.
- Copyright headers in modified files must be marked to show they were changed.

## 2. Strongly Recommended (Professional Convention, Not Legally Mandatory)

These reinforce attribution and professional credibility without adding legal restrictions:

1. **Per-script header block** — every script displays Author, Copyright, License, GitHub link, and LinkedIn (see [`SCRIPT_HEADER_TEMPLATE.md`](SCRIPT_HEADER_TEMPLATE.md)). This travels with the file wherever it's copied.
2. **README "Author" section** — a clear, professional author section (name, title, company, LinkedIn, GitHub) at the top level and repeated in tool-level READMEs where practical.
3. **Consistent copyright line** — `Copyright © 2026 Benson Lam` in the README footer, LICENSE appendix, and NOTICE file, kept in sync as years/versions change.
4. **GitHub "About" and social preview** — name and LinkedIn link surfaced in the repository's About sidebar and social preview image, so attribution is visible even before someone opens a file.
5. **Consistent GitHub handle and LinkedIn link** — used identically across README, NOTICE, script headers, and release notes, so attribution is easy to verify and hard to accidentally strip.
6. **CHANGELOG and Release notes** — each release credits the maintainer and, where relevant, named contributors, reinforcing an ongoing paper trail of authorship over time.
7. **"Built by" footer convention** — where a tool produces a dashboard or report output, consider including a small, unobtrusive `Generated by Engineer (github.com/<user>/Engineer) — Benson Lam` footer/comment in generated output, where appropriate and non-intrusive to the end business user.

## 3. What This Project Deliberately Avoids

To stay genuinely community-friendly and maximise adoption, this project **does not**:

- Add custom license clauses beyond Apache 2.0 (e.g., "must display attribution in UI") — this would technically make the license non-standard and could deter adoption/legal review by companies.
- Require contributors to reassign copyright — contributors retain copyright over their own contributions, consistent with Apache 2.0 Section 5, while agreeing their contribution is licensed under the same terms.
- Use aggressive branding (e.g., watermarking script output, forcing telemetry/callbacks) — this would undermine trust and adoption, and is inconsistent with a genuinely open tool.

## 4. Summary

Attribution is maintained through **consistent, professional convention** — headers, README structure, NOTICE file, and release hygiene — rather than through restrictive licensing. This keeps the project genuinely Apache 2.0 compliant and attractive for broad community and commercial adoption, while ensuring Benson Lam's authorship remains clear, consistent, and professionally presented throughout.
